### مقدمة

******

يوفر Angus Mail لنصوص AutoJs6 البرمجية كائنا عاما باسم `mail` لإرسال الرسائل, وسرد صناديق البريد والبحث فيها, وقراءة نصوص الرسائل, وتنزيل المرفقات, وإدارة العلامات والمجلدات, ومراقبة وصول بريد جديد إلى مجلد. يعتمد على [Eclipse Angus Mail](https://eclipse-ee4j.github.io/angus-mail/) 2.0.5, التنفيذ المرجعي لـ Jakarta Mail, ويتعامل مع IMAP و POP3 و SMTP عبر TLS.

تبقى كل حركة البريد داخل عملية المكون الإضافي. يكتشف AutoJs6 المكون الإضافي عبر خدمة Binder الخاصة به, ويسلمه الحساب الذي يقدمه النص البرمجي (أو اسما مستعارا محفوظا في صفحة إعدادات المكون الإضافي), ويتلقى نتائج JSON وتدفقات المرفقات; ولا يحتوي المضيف نفسه على أي شيفرة بريد. تبقى بيانات الاعتماد في الذاكرة طوال مدة الجلسة فقط ما لم تختر حفظ حساب في المكون الإضافي.

******

### الميزات

******

توفر الإضافة القدرات التالية:

- الإرسال: نص عادي أو HTML, وعدة مستلمين, ومرفقات وصور مضمنة, وترويسات مخصصة وأولوية, مع حفظ نسخة المرسل على الخادم عندما لا يقوم المزود بذلك بنفسه.
- الاستقبال: سرد مجلد صفحة بصفحة, والبحث على الخادم (مع الرجوع إلى ترشيح على جانب العميل لدى المزودين الذين يرفضون البحث بغير ASCII), وقراءة النصوص بصيغتي النص و HTML, وتنزيل المرفقات مباشرة إلى دليل عمل النص البرمجي.
- التنظيم: وضع علامة مقروء أو مميز, والنقل, والنسخ, والحذف, والحذف النهائي, وإنشاء المجلدات وإعادة تسميتها وحذفها; تحصل حسابات POP3 على المجموعة الفرعية للقراءة فقط.
- المراقبة: تلقي أحداث البريد الجديد طوال مدة تشغيل النص البرمجي, عبر IMAP IDLE حيث يدفع الخادم فعلا وعبر الاستطلاع الدوري (60 ثانية افتراضيا, قابل للضبط) حيث لا يفعل: QQ و Sina يقبلان IDLE لكنهما لا يرسلان شيئا, و 163 و 126 بلا IDLE, وحسابات POP3 تستطلع دائما; تنجو المراقبة من انقطاع الشبكة ومن إعادة تشغيل عملية الإضافة.
- المزودون: إعدادات مسبقة لـ Gmail و Outlook.com و Microsoft 365 و QQ و 163 و 126 و iCloud و Yahoo و Sina و Aliyun تملأ المضيفين والمنافذ والتشفير; ويمكن تجاوز أي حقل لخوادم أخرى.
- المصادقة: كلمات المرور ورموز التفويض من المزودين, أو رموز وصول XOAUTH2 يقدمها النص البرمجي مع دالة تجديد.

### الاستخدام

******

1. ثبت ملف APK للمكون الإضافي من [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Angus-Mail/releases) على جهاز مثبت عليه AutoJs6 بالبنية 5282 (6.8.0) أو أحدث.
2. افتح مركز المكونات الإضافية في AutoJs6, وتأكد من التعرف على `Angus Mail` ثم فعله.
3. جهز الحساب: فعل IMAP أو POP3 و SMTP في إعدادات الويب لدى مزود البريد واحصل على رمز تفويض (QQ و 163 و 126 و Sina) أو كلمة مرور تطبيق (Gmail و iCloud و Yahoo) أو رمز وصول OAuth 2.0 (Outlook.com); كلمة مرور تسجيل الدخول نفسها لا تقبل عادة.
4. استدع `mail.connect(...)` في نص برمجي, أو احفظ الحساب في صفحة إعدادات المكون الإضافي (أيقونته في المشغل, أو AutoJs6 > خيارات المطور > إعدادات حسابات البريد) واتصل بالاسم المستعار.

### تجهيز مزودي الخدمة

******

يحتاج كل مزود أولا إلى تفعيل IMAP (أو POP3) و SMTP في إعدادات الويب, وإلى رمز تفويض أو كلمة مرور تطبيق أو رمز وصول بدلا من كلمة مرور تسجيل الدخول; أهم ما يخص كل إعداد مسبق (قيمة `provider`):

- بريد QQ (`qq`): فعل خدمة IMAP/SMTP في إعدادات الحساب على الويب وأنشئ رمز تفويض يستخدم بوصفه `password`.
- 163 / 126 / yeah.net (`163` و `126`; يستخدم yeah.net الإعداد المسبق `163` مع استبدال المضيفين): فعل الخدمات في صفحة POP3/SMTP/IMAP من إعدادات الويب وأنشئ رمز تفويض; يفعل POP3 على حدة, وإلا رفض POP3 الرمز الذي يقبله IMAP و SMTP. تشترط الخوادم أن يرسل كل اتصال IMAP الأمر `ID` أولا (وإلا أجابت `Unsafe Login`); ويتولى المكون الإضافي ذلك بنفسه.
- بريد Sina (`sina`): فعل خدمة IMAP/SMTP في إعدادات العميل على الويب واستخدم رمز التفويض. لا يحتفظ الخادم بنسخة من البريد المرسل (يضيف المكون الإضافي نسخة إلى مجلد المرسل), ويرفض إنشاء المجلدات عبر IMAP, وتجري عمليات البحث النصي على جهة العميل.
- Gmail (`gmail`): بعد تفعيل التحقق بخطوتين أنشئ كلمة مرور تطبيق في حساب Google واستخدمها بوصفها `password`, أو قدم رمز وصول OAuth 2.0 بالنطاق `https://mail.google.com/` (`accessToken` مع `tokenProvider`); توجد المجلدات ضمن مساحة الأسماء `[Gmail]` ويصل البريد الجديد عبر IDLE. تحقق المشروع من الحساب الحقيقي برمز وصول.
- Outlook.com / Hotmail (`outlook`) و Microsoft 365 (`office365`): عطلت Microsoft المصادقة الأساسية للحسابات الشخصية, لذا ترفض كلمات مرور التطبيقات على IMAP و POP3 و SMTP, ولا يقبل الإعداد المسبق `outlook` سوى رمز وصول OAuth 2.0 (`accessToken` مع `tokenProvider`); تقبل حسابات العمل أو المدرسة (`office365`) كلمة مرور أو رمز وصول, لكن سياسة المستأجر قد تعطل IMAP أو POP3 أو SMTP AUTH. يحتاج الرمز إلى النطاقات المفوضة `IMAP.AccessAsUser.All` و `POP.AccessAsUser.All` و `SMTP.Send` من `https://outlook.office.com/` (تحقق المشروع من حساب شخصي بمثل هذا الرمز: IMAP و POP3 و SMTP ودفع IDLE); في بعض صناديق البريد الشخصية الأحدث عطلت Microsoft مصادقة SMTP AUTH (`535 5.7.139`) ولا يوجد إعداد للمستخدم يفعلها.
- iCloud (`icloud`): أنشئ كلمة مرور خاصة بالتطبيق في حساب Apple; لا توجد خدمة POP3.
- Yahoo (`yahoo`) وبريد Aliyun الشخصي (`aliyun`): أنشئ كلمة مرور تطبيق أو رمز تفويض; يتبع هذان الإعدادان المسبقان التوثيق العام ولم يتم التحقق منهما لأن المشروع لا يملك حساب اختبار.

للخوادم الأخرى يترك `provider` فارغا وتحدد `host` و `port` و `tls` (`ssl` أو `starttls` أو `none`) لكل من `imap` (أو `pop3`) و `smtp`; ويمكن أيضا استبدال أي حقل من حقول الإعداد المسبق. جميع الخيارات موصوفة في [MailAccountOptions](https://docs.autojs6.com/#/mailAccountOptionsType), ويعرض `mail.providers.list()` الإعدادات المسبقة المدمجة.

### بداية سريعة

******

نص برمجي يتصل بالاسم المستعار, ويرسل تقريرا, ويقرأ البريد غير المقروء مع مرفقاته, ويراقب رمز تحقق, ويبحث بشكل غير متزامن:

```js
// A saved alias keeps the credential inside the plugin; an inline account works as well:
// mail.connect({ provider: 'qq', address: 'me@qq.com', password: 'authorization-code' })
let client = mail.connect('work');

client.send({ to: 'you@example.com', subject: 'Report', text: 'See the attachment', attachments: ['/sdcard/report.xlsx'] });

client.fetch({ unseenOnly: true, limit: 10 }).forEach(m => {
    let full = m.load();
    full.attachments.forEach(a => a.download(files.join(files.cwd(), 'mail-attachments')));
    client.markRead(m);
});

let watch = client.watch('INBOX', { fetchBody: true });
watch.on('message', m => { if (/code/i.test(m.subject)) console.log(m.text); });
watch.on('error', e => console.warn(e.code, e.message));

// Every network method also has an Async form; every failure is a MailError with a code.
mail.setDefault(client);
mail.searchAsync({ subject: 'invoice', since: '2026-09-01' }).then(list => console.log(list.length, list.fallback));
```

### الحسابات المحفوظة والأسماء المستعارة

******

الاسم المستعار هو حساب محفوظ داخل المكون الإضافي. بعد إدخال الحساب واختباره وحفظه في صفحة إعدادات المكون الإضافي (أيقونته في المشغل, أو AutoJs6 > خيارات المطور > إعدادات حسابات البريد), تخزن كلمة المرور أو رمز الوصول مشفرة بمفتاح Android Keystore في الدليل الخاص بالمكون الإضافي وتستثنى من النسخ الاحتياطي; ثم تتصل النصوص البرمجية عبر `mail.connect('alias')`, ولا تمر بيانات الاعتماد عبر النص البرمجي ولا عبر Binder.

يمكن لصفحة الإعدادات تعليم حساب واحد بوصفه الافتراضي; تحمل العناصر التي يعيدها `mail.accounts.list()` القيمة `default: true` لهذا الحساب, ويتحقق `mail.accounts.has(alias)` من وجود الاسم المستعار. أنشئ عميلا لكل اسم مستعار عند استخدام عدة حسابات معا; وبعد `mail.setDefault(client)` تعمل الأساليب المحولة مثل `mail.fetch(...)` على العميل الافتراضي.

### التوافق

******

الاستنتاجات التالية مستمدة من مصفوفة الحسابات الحقيقية للمرحلة P6 (2026-09-19 و 09-20: أرسل كل مزود رسالة إلى نفسه بموضوع ونص وأسماء عرض واسم ملف بالصينية, ثم جرى التحقق من كل عملية), ومن مصفوفات TLS ومجموعات الأحرف ودورة الحياة والأداء:

- بريد QQ: الإرسال والإدراج والنصوص والمرفقات والعلامات والنقل (`MOVE`) و POP3 كلها ناجحة; يجيب الخادم عن البحث بالصينية بصفر نتائج بدلا من خطأ, لذا يلزم `fallback: 'always'`; يعيد الخادم كتابة Message-ID للبريد الصادر; يرفض إنشاء المجلدات; تعمل المراقبة بالاستطلاع الدوري (IDLE لا يدفع أبدا), ويصبح البريد الجديد مرئيا على الخادم بعد 15-40 ثانية من التسليم.
- 163 / 126 / yeah.net: كلها ناجحة; يحتفظ الخادم بنسخة المرسل; لا يوجد IDLE فتعمل المراقبة بالاستطلاع; يجيب 163 عن البحث النصي في البريد الحديث بصفر نتائج (126 و yeah.net يعملان); تعود المسافات في اسم عرض المرسل شرطات سفلية; يجب تفعيل POP3 على yeah.net على حدة في إعدادات الويب.
- بريد Sina: ناجح; لا يقبل الخادم سوى شروط ALL و SINCE والعلامات, فتتحول عمليات البحث النصي تلقائيا إلى التصفية على جهة العميل; لا يوجد IDLE; يرفض إنشاء المجلدات; يضيف المكون الإضافي نسخة المرسل.
- Gmail: كل الصفوف ناجحة برمز وصول OAuth 2.0, ويصل البريد الجديد عبر IDLE (نحو 30 ثانية, وهو إيقاع إشعارات Gmail نفسه); تنجح كل عمليات البحث على الخادم بما فيها الصينية (لا يفعل المكون الإضافي `UTF8=ACCEPT`); تخزن كلمات IMAP المفتاحية المخصصة (الوحيد بين الستة); لا يتضمن عرض POP3 البريد الذي أرسله الحساب إلى نفسه.
- Outlook.com / Hotmail: برمز وصول OAuth 2.0 تمر كل الصفوف على حساب شخصي واحد (2026-09-21): أدوار المجلدات من الأسماء المتعارف عليها, يحتفظ الخادم بنسخة المرسل ويعيد كتابة Message-ID, يعمل `MOVE` وإنشاء المجلدات, يسجل POP3 الدخول بصيغة السطرين من `AUTH XOAUTH2`, ويدفع IDLE خلال نحو 10 ثوان (الأسرع بين المزودين السبعة); البحث في الخادم عن عنوان صيني يصيب لكنه قد يستغرق دقائق; ما زالت كلمات مرور التطبيقات مرفوضة على IMAP و POP3 و SMTP (`AUTH_MECHANISM_UNSUPPORTED`), وفي بعض صناديق البريد الشخصية الأحدث عطلت Microsoft مصادقة SMTP AUTH (`535 5.7.139`); لا توجد حسابات اختبار لكل من iCloud و Yahoo و Aliyun وإعداداتها المسبقة غير متحقق منها.
- TLS ومجموعات الأحرف: اختبر SSL الضمني و STARTTLS والنص الصريح والشهادات الموقعة ذاتيا (مع `tls.trustAll` وبدونه) وعدم تطابق اسم المضيف وعدم تطابق وضع المنفذ واحدا واحدا على IMAP و POP3 و SMTP, وتقابل الإخفاقات رموزا مميزة مثل `TLS_FAILED` و `TIMEOUT`; وجرى التحقق من الموضوعات وأسماء العرض والنصوص وأسماء الملفات بترميزات GB18030 و GBK و GB2312 و Big5 و ISO-2022-JP و EUC-KR و UTF-8 في الحالات المعلنة وغير المعلنة والمعلنة خطأ.
- الأجهزة ودورة الحياة: محاكي Android 7.0 (API 24) وهاتفا Sony (Android 9) و Redmi (Android 13); تحرر الاتصالات والارتباطات والخيوط في ثماني طرق لإنهاء النص البرمجي (الخروج العادي, و `exit()`, و `engines.stopAll()`, والإيقاف القسري للمضيف أو المكون الإضافي, والترقية في المكان, وتعطيل المكون الإضافي وإلغاء تثبيته); مع إطفاء الشاشة (Doze) تفقد المراقبة اتصالها وتستعيده عند استيقاظ الجهاز, ويمكن لصفحة الإعدادات طلب الإعفاء من تحسين البطارية لمراقبة دون انقطاع.
- خط الأساس للأداء: الإدراج والبحث والتنزيل والإرسال وساعة من الانتظار في IDLE على صندوق وارد محلي من 10000 رسالة مع مرفق بحجم 50 MiB على JVM و Redmi و Sony مسجلة في `docs/dev/p6-performance-baseline.md`; مستندات الرسائل محدودة (للعناوين والترويسات وشجرة MIME والنصوص المضمنة حدود), فلا تستطيع المدخلات العدائية تفجير الجلسة.

### الأسئلة الشائعة

******

- **كيف أتحرى `AUTH_FAILED`?** تأكد من استخدام رمز التفويض أو كلمة مرور التطبيق لا كلمة مرور تسجيل الدخول, ومن تفعيل البروتوكول في إعدادات الويب (يفعل IMAP و POP3 كل على حدة); واستدع `client.test()` لترى نتيجة نقطة الاستقبال و SMTP ورمز الخطأ لكل منهما على حدة. في حسابات رموز الوصول يعني `AUTH_FAILED` عادة انتهاء صلاحية الرمز; ومع وجود `tokenProvider` يجدده المكون الإضافي ويعيد المحاولة مرة واحدة. تبين حقول الخطأ `code` و `details` و `retryable` ما إذا كانت إعادة المحاولة مجدية.
- **يجيب 163 / 126 بـ `Unsafe Login`?** ترفض خوادم IMAP لدى NetEase الاتصالات التي لم ترسل الأمر `ID`; يرسل المكون الإضافي `ID` مباشرة بعد تسجيل الدخول على كل اتصال IMAP, فلا ينبغي أن يحدث ذلك. وإن حدث مع ذلك, فأعد تفعيل خدمة IMAP في إعدادات الويب وأنشئ رمز تفويض جديدا.
- **البحث بالصينية لا يجد شيئا?** تتعامل الخوادم مع البحث بغير ASCII بطرق مختلفة: يرفضه Sina (فيتحول المكون الإضافي بنفسه إلى التصفية على جهة العميل), بينما يجيب QQ و 163 بصفر نتائج دون خطأ (لا ينطلق `fallback: 'client'` الافتراضي). استخدم `fallback: 'always'` على هذه الحسابات وضيق النطاق بـ `since` أو `limit`; تجلب تصفية النصوص على جهة العميل كل مرشح على حدة وقد تكون بطيئة في صندوق بريد كبير.
- **نجح `mail.connect` لكن أول `fetch` يفشل?** يفتح `connect` جلسة المكون الإضافي فقط ولا يتصل بخادم البريد; وأول أسلوب شبكي هو الذي يسجل الدخول (SMTP عند أول إرسال). استدع `client.test()` للتحقق من الحساب مسبقا.
- **تتوقف المراقبة بعد إطفاء الشاشة?** يجمد Doze في Android شبكة التطبيقات في الخلفية, فتفقد المراقبة اتصالها ويبلغ عن البريد الجديد بعد دقائق من استيقاظ الجهاز (يعيد المكون الإضافي الاتصال فور انتهاء Doze). لمراقبة دون انقطاع, استخدم زر الإرشاد في صفحة الإعدادات لطلب الإعفاء من تحسين البطارية; ولا تعيش المراقبة إلا أثناء تشغيل النص البرمجي وتغلق عند انتهائه.
- **كيف أوصل Outlook.com / Hotmail?** عطلت Microsoft المصادقة الأساسية للحسابات الشخصية, لذا يجب أن ينتج تدفق تفويض OAuth 2.0 (يحتاج إلى تطبيق مسجل) رمز وصول بنطاقات IMAP و POP و SMTP; مرره بوصفه `accessToken` وجدده عبر `tokenProvider`. لا يقبل الإعداد المسبق أي كلمة مرور.
- **ماذا يستطيع حساب POP3?** لا يوجد سوى `INBOX` و `uid` هو سلسلة UIDL; يعمل الإدراج والقراءة والتنزيل والحذف والمراقبة بالاستطلاع, بينما تجيب العلامات والنقل والنسخ والإلحاق والمسح وإدارة المجلدات بـ `UNSUPPORTED_OPERATION`; ويجري البحث على جهة العميل بشروط الغلاف فقط.

### الصلاحيات والأمان

******

يلتزم المكون الإضافي بحدود صريحة:

- نقاط دخول Binder محمية بإذن التوقيع `org.autojs.permission.PLUGIN`, لذا لا يمكن الوصول إليها إلا من AutoJs6; ولا يصدر المكون الإضافي أي مكونات أخرى.
- يخدم إذن INTERNET اتصالات IMAP و POP3 و SMTP بالخوادم التي يحددها النص البرمجي فقط; ولا يجري المكون الإضافي أي طلبات أخرى ولا يجمع أي بيانات.
- تنتقل كلمات المرور والرموز من النص البرمجي إلى المكون الإضافي في حقول Binder مخصصة, ولا تظهر أبدا في السجلات أو مستندات JSON أو رسائل الخطأ أو تقارير الأعطال, ولا تبقى في الذاكرة إلا طوال مدة الجلسة. الحسابات المحفوظة في صفحة الإعدادات مشفرة بمفتاح Android Keystore ومستبعدة من النسخ الاحتياطي.
- تستخدم الاتصالات TLS افتراضيا (SSL أو STARTTLS حسب متطلبات المزود); ويجب طلب الاتصالات غير المشفرة والشهادات الموقعة ذاتيا صراحة لكل حساب.
- إذن REQUEST_IGNORE_BATTERY_OPTIMIZATIONS يخدم زر الإرشاد في صفحة الإعدادات فقط: يعرض الزر ما إذا كان النظام قد يوقف الإضافة مؤقتا في الخلفية, ويفتح مربع حوار النظام عند الطلب; لا تطلب الإضافة ذلك من تلقاء نفسها, ولا تعتمد أي ميزة على هذا الاستثناء. قاست مصفوفة المراقبة في P5 فائدة هذا الاستثناء: بعد انطفاء الشاشة لفترة (Doze) يجمد Android شبكة تطبيقات الخلفية, فتفقد المراقبة اتصالها, وتنتهي مهلة إعادة اتصالها, ولا يبلغ عن البريد الجديد إلا بعد دقائق من استيقاظ الجهاز (نحو أربع دقائق على Android 9; وتعيد الإضافة الاتصال فورا عند انتهاء Doze); ومع الاستثناء تبقى المراقبة متصلة.

احصل على المكون الإضافي فقط من صفحة [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Angus-Mail/releases) الرسمية أو من مركز المكونات الإضافية في AutoJs6. قد تفشل الحزم من مصادر غير معروفة في التحقق من المضيف أو تحمل مخاطر حتى لو بدا رقم الإصدار متطابقا.

application id: io.github.supermonster003.autojs6.plugin.angus.mail
plugin id: angus-mail
engine: mail
variant: default
service action: org.autojs.plugin.MAIL
service category: mail
info action: org.autojs.plugin.INFO
aidl interface: org.autojs.plugin.mail.api.IMailPlugin

### البناء والتحقق

******

يستهدف هذا القسم المطورين الراغبين في بناء المكون الإضافي من المصدر; ويمكن للمستخدمين العاديين ببساطة تثبيت ملف APK الجاهز من صفحة Releases.

بناء APK للتصحيح:

```powershell
.\gradlew.bat :app:assembleDebug
```

تشغيل اختبارات وحدة JVM وبناء APK اختبارات الأجهزة:

```powershell
.\gradlew.bat :mail-core:test :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

بناء APK الإصدار:

```powershell
.\gradlew.bat :app:assembleRelease
```

جمع ناتج الإصدار وإلحاق الإصدار وملخص CRC32 باسم الملف:

```powershell
.\gradlew.bat :app:appendDigestToReleasedFiles
```

التحقق من تزامن مصادر التوثيق متعدد اللغات مع النواتج المولدة (يفرض ذلك CI أيضا):

```powershell
py .python\generate_markdown.py --check
```

يتطلب البناء JDK 21 أو أحدث و Android SDK 37; وتدار إصدارات Gradle والمكونات الإضافية مركزيا عبر `version.properties` و `io.github.supermonster003.autojs6-platform-versions`.

### التعريب وتوليد التوثيق

******

```text
.readme/common.json
.readme/lang_*.json
.readme/template_readme.md
.readme/template_plugin_instruction.md
.changelog/lang_*.json
.changelog/template_changelog.md
.python/generate_markdown.py
app/src/main/assets/doc/CHANGELOG-*.md
app/src/main/res/raw-*/plugin_instruction.md
```

ملفات JSON اللغوية في `.readme/` و `.changelog/` هي المصدر الوحيد لملف README وتعليمات مركز المكونات الإضافية وسجل التغييرات. عدل دائما مصادر JSON هذه وأعد تشغيل `py .python/generate_markdown.py`; ولا تحرر يدويا نواتج README و `plugin_instruction.md` وسجل التغييرات المولدة أبدا. شغل `py .python/generate_markdown.py --check` للتحقق من جميع النواتج المولدة.
