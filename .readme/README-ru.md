### Введение

******

Angus Mail предоставляет скриптам AutoJs6 глобальный объект `mail` для отправки сообщений, просмотра и поиска в почтовых ящиках, чтения текста писем, загрузки вложений, управления флагами и папками, а также отслеживания новых писем в папке. Плагин построен на [Eclipse Angus Mail](https://eclipse-ee4j.github.io/angus-mail/) 2.0.5, эталонной реализации Jakarta Mail, и работает с IMAP, POP3 и SMTP поверх TLS.

Весь почтовый трафик остается внутри процесса плагина. AutoJs6 находит плагин через его Binder-сервис, передает учетную запись, указанную скриптом (или псевдоним, сохраненный на странице настроек плагина), и получает результаты в JSON и потоки вложений; в самом хосте нет почтового кода. Учетные данные хранятся в памяти только в течение сеанса, если вы не решите сохранить учетную запись в плагине.

### Возможности

******

Плагин предоставляет следующие возможности:

- Отправка: обычный текст или HTML, несколько получателей, вложения и встроенные изображения, собственные заголовки и приоритет; копия отправленного письма сохраняется на сервере, если провайдер не делает этого сам.
- Получение: постраничный список папки, поиск на сервере (с переходом на фильтрацию на стороне клиента у провайдеров, которые отклоняют поиск не по ASCII), чтение текстовой и HTML-версии письма и загрузка вложений прямо в рабочий каталог скрипта.
- Упорядочивание: пометка прочитанным или флагом, перемещение, копирование, удаление, очистка, а также создание, переименование и удаление папок; учетные записи POP3 получают подмножество только для чтения.
- Отслеживание: события о новых письмах, пока выполняется скрипт, через IMAP IDLE там, где сервер действительно присылает уведомления, и через опрос (по умолчанию 60 с, настраивается) там, где нет: QQ и Sina принимают IDLE, но молчат, у 163 и 126 нет IDLE, учетные записи POP3 всегда опрашиваются; отслеживание переживает потерю сети и перезапуск процесса плагина.
- Фоновое наблюдение: страница наблюдений в настройках держит соединения IMAP IDLE или опроса с сохранёнными учётными записями в службе переднего плана, пока не запущен ни один скрипт, записывает каждое новое письмо и будит задачу AutoJs6 "При получении письма" для выбранного наблюдения, с необязательным фильтром по отправителю и теме; письмо передаётся скрипту в `engines.myEngine().execArgv.mail`.
- Провайдеры: предустановки для Gmail, Outlook.com, Microsoft 365, QQ, 163, 126, iCloud, Yahoo, Sina и Aliyun заполняют хосты, порты и шифрование; любое поле можно переопределить для других серверов.
- Аутентификация: пароли и коды авторизации провайдеров или токены доступа XOAUTH2, которые скрипт передает вместе с функцией обновления.
- Вход через браузер: учетную запись Gmail, Outlook.com или Microsoft 365 можно добавить, войдя в учетную запись Google или Microsoft в системном браузере из настроек плагина (код авторизации OAuth 2.0 с PKCE); плагин хранит токен обновления в зашифрованном виде на устройстве, обновляет токен доступа перед каждым сеансом и показывает состояние входа с действиями "Войти заново" и "Отозвать вход" на странице учетных записей. Скрипты по-прежнему подключаются по псевдониму и никогда не видят токен.

### Использование

******

1. Установите APK плагина из [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Angus-Mail/releases) на устройство с AutoJs6 сборки 5282 (6.8.0) или новее.
2. Откройте центр плагинов AutoJs6, убедитесь, что `Angus Mail` распознан, и включите его.
3. Подготовьте учетную запись: включите IMAP или POP3 и SMTP в веб-настройках провайдера и получите код авторизации (QQ, 163, 126, Sina) или пароль приложения (Gmail, iCloud, Yahoo); сам пароль входа обычно не принимается. Для учетных записей Gmail, Outlook.com и Microsoft 365 можно вместо этого войти в учетную запись Google или Microsoft через браузер из настроек плагина (выберите аутентификацию "Войти через Google / Microsoft (браузер)") или указать токен доступа OAuth 2.0, полученный в другом месте.
4. Вызовите `mail.connect(...)` в скрипте или сохраните учетную запись на странице настроек плагина (значок плагина в лаунчере или AutoJs6 > Параметры разработчика > Настройки почтовых учетных записей) и подключайтесь по псевдониму.
5. Чтобы запускать скрипт по новому письму, не держа его запущенным: добавьте наблюдение на странице наблюдений плагина (настройки > Наблюдения: псевдоним учётной записи, папка, режим, фильтры), разрешите уведомление по запросу, затем создайте задачу в AutoJs6 (долгое нажатие на скрипт > задача по расписанию > по рассылке > При получении письма) и выберите наблюдение; задаче нужна сборка AutoJs6 с версией почтового контракта 2.

### Подготовка провайдеров

******

У каждого провайдера сначала нужно включить IMAP (или POP3) и SMTP в веб-настройках и использовать вместо пароля для входа код авторизации, пароль приложения или токен доступа; главное по каждой предустановке (значение `provider`):

- QQ Mail (`qq`): включите службу IMAP/SMTP в веб-настройках учетной записи и сгенерируйте код авторизации, который используется как `password`.
- 163 / 126 / yeah.net (`163`, `126`; yeah.net использует предустановку `163` с переопределенными хостами): включите службы на странице POP3/SMTP/IMAP веб-настроек и сгенерируйте код авторизации; POP3 включается отдельно, иначе POP3 отвергает код, который принимают IMAP и SMTP. Серверы требуют, чтобы каждое IMAP-соединение сначала отправляло команду `ID` (иначе отвечают `Unsafe Login`); плагин делает это сам.
- Sina Mail (`sina`): включите службу IMAP/SMTP в веб-настройках клиента и используйте код авторизации. Сервер не хранит копии отправленных писем (плагин добавляет их в папку отправленных), отвергает создание папок по IMAP, а текстовый поиск выполняется на клиенте.
- Самый простой путь - вход через браузер на странице настроек плагина ("Войти через Google (браузер)"): пароль приложения не нужен, токен обновляется сам. Иначе: Gmail (`gmail`): при включенной двухэтапной аутентификации создайте пароль приложения в аккаунте Google и используйте его как `password` либо передайте токен доступа OAuth 2.0 с областью `https://mail.google.com/` (`accessToken` и `tokenProvider`); папки находятся в пространстве имен `[Gmail]`, новые письма приходят через IDLE. Проект проверил реальную учетную запись с токеном.
- Самый простой путь - вход через браузер на странице настроек плагина ("Войти через Microsoft (браузер)"): плагин сам получает и обновляет токен. Иначе: Outlook.com / Hotmail (`outlook`) и Microsoft 365 (`office365`): Microsoft отключила базовую аутентификацию для личных учетных записей, поэтому пароли приложений отвергаются на IMAP, POP3 и SMTP, и предустановка `outlook` принимает только токен доступа OAuth 2.0 (`accessToken` и `tokenProvider`); рабочие и учебные учетные записи (`office365`) принимают пароль или токен, но политика арендатора может отключить IMAP, POP3 или SMTP AUTH. Токену нужны делегированные области `IMAP.AccessAsUser.All`, `POP.AccessAsUser.All` и `SMTP.Send` из `https://outlook.office.com/` (проект проверил личную учетную запись с таким токеном: IMAP, POP3, SMTP и уведомления IDLE); в некоторых новых личных ящиках Microsoft отключила SMTP AUTH (`535 5.7.139`), и никакая настройка пользователя ее не включает.
- iCloud (`icloud`): создайте пароль для приложения в учетной записи Apple; службы POP3 нет.
- Yahoo (`yahoo`) и личная почта Aliyun (`aliyun`): создайте пароль приложения или код авторизации; эти две предустановки составлены по открытой документации и не проверены, так как у проекта нет тестовой учетной записи.

Для других серверов `provider` не указывается, а для `imap` (или `pop3`) и `smtp` задаются `host`, `port` и `tls` (`ssl`, `starttls` или `none`); любое поле предустановки также можно переопределить. Все параметры описаны в [MailAccountOptions](https://docs.autojs6.com/#/mailAccountOptionsType), встроенные предустановки показывает `mail.providers.list()`.

### Быстрый старт

******

Скрипт, который подключается по псевдониму, отправляет отчет, читает непрочитанные письма с вложениями, ждет код подтверждения и ищет асинхронно:

```js
// A saved alias keeps the credential inside the plugin; an inline account works as well:
// mail.connect({ provider: 'qq', address: 'me@qq.com', password: 'authorization-code' })
let client = mail.connect('work');

client.send({ to: 'you@example.com', subject: 'Report', text: 'See the attachment', attachments: ['/sdcard/report.xlsx'] });

client.fetch({ unseenOnly: true, limit: 10 }).forEach(m => {
    let full = m.load();
    full.attachments.forEach(a => a.download(files.join(files.cwd(), 'mail-attachments')));
    client.markRead(m);
});

let watch = client.watch('INBOX', { fetchBody: true });
watch.on('message', m => { if (/code/i.test(m.subject)) console.log(m.text); });
watch.on('error', e => console.warn(e.code, e.message));

// Every network method also has an Async form; every failure is a MailError with a code.
mail.setDefault(client);
mail.searchAsync({ subject: 'invoice', since: '2026-09-01' }).then(list => console.log(list.length, list.fallback));
```

### Сохраненные учетные записи и псевдонимы

******

Псевдоним - это учетная запись, сохраненная внутри плагина. После ввода, проверки соединения и сохранения на странице настроек плагина (значок в лаунчере или AutoJs6 > Параметры разработчика > Настройки почтовых учетных записей) пароль или токен хранится зашифрованным ключом Android Keystore в приватном каталоге плагина и исключается из резервных копий; далее скрипты подключаются через `mail.connect('псевдоним')`, и учетные данные не проходят ни через скрипт, ни через Binder.

На странице настроек одну учетную запись можно отметить как учетную запись по умолчанию; в записях, возвращаемых `mail.accounts.list()`, у нее стоит `default: true`, а `mail.accounts.has(alias)` проверяет наличие псевдонима. При одновременной работе с несколькими учетными записями создавайте по клиенту на псевдоним; после `mail.setDefault(client)` переадресованные методы вроде `mail.fetch(...)` действуют на клиент по умолчанию.

### Совместимость

******

Выводы ниже получены из матрицы реальных учетных записей этапа P6 (2026-09-19 и 09-20: каждый провайдер отправил сам себе письмо с китайскими темой, текстом, отображаемыми именами и именем файла, после чего проверялась каждая операция), а также из матриц TLS, кодировок, жизненного цикла и производительности:

- QQ Mail: отправка, списки, тексты, вложения, флаги, перемещение (`MOVE`) и POP3 проходят; на поиск по-китайски сервер отвечает нулем совпадений вместо ошибки, поэтому нужен `fallback: 'always'`; Message-ID исходящих писем переписывается сервером; создание папок отвергается; отслеживание идет опросом (IDLE ничего не присылает), новые письма становятся видны на сервере через 15-40 с после доставки.
- 163 / 126 / yeah.net: все проходит; сервер хранит копию отправленного; IDLE нет, отслеживание идет опросом; 163 отвечает нулем совпадений на текстовый поиск по недавним письмам (126 и yeah.net в порядке); пробелы в отображаемом имени отправителя возвращаются подчеркиваниями; POP3 на yeah.net включается отдельно в веб-настройках.
- Sina Mail: проходит; сервер принимает только условия ALL, SINCE и флаги, поэтому текстовый поиск автоматически переходит на клиентскую фильтрацию; IDLE нет; создание папок отвергается; копию отправленного добавляет плагин.
- Gmail: все строки проходят с токеном OAuth 2.0, новые письма приходят через IDLE (около 30 с, собственный ритм уведомлений Gmail); серверный поиск, включая китайский, находит все (плагин не включает `UTF8=ACCEPT`); пользовательские ключевые слова IMAP сохраняются (единственный из шести); в представлении POP3 нет писем, которые учетная запись отправила сама себе.
- Outlook.com / Hotmail: с токеном OAuth 2.0 все строки проходят на одной личной учетной записи (2026-09-21): роли папок по общепринятым именам, сервер хранит копию отправленного и переписывает Message-ID, `MOVE` и создание папок работают, POP3 входит двухстрочным `AUTH XOAUTH2`, IDLE уведомляет примерно за 10 с (быстрее всех семи провайдеров); серверный поиск по китайской теме находит письмо, но может занять минуты; пароли приложений по-прежнему отвергаются на IMAP, POP3 и SMTP (`AUTH_MECHANISM_UNSUPPORTED`), а в некоторых новых личных ящиках Microsoft отключила SMTP AUTH (`535 5.7.139`); для iCloud, Yahoo и Aliyun нет тестовых учетных записей, их предустановки не проверены.
- TLS и кодировки: неявный SSL, STARTTLS, открытый текст, самоподписанные сертификаты (с `tls.trustAll` и без), несовпадение имени хоста и несоответствие режима порта проверены по отдельности на IMAP, POP3 и SMTP, а сбои отображаются в различимые коды вроде `TLS_FAILED` и `TIMEOUT`; темы, отображаемые имена, тексты и имена файлов в GB18030, GBK, GB2312, Big5, ISO-2022-JP, EUC-KR и UTF-8 проверены в объявленном, необъявленном и неверно объявленном вариантах.
- Устройства и жизненный цикл: эмулятор Android 7.0 (API 24), а также телефоны Sony (Android 9) и Redmi (Android 13); соединения, привязки и потоки освобождаются при восьми способах завершения скрипта (обычный выход, `exit()`, `engines.stopAll()`, принудительная остановка хоста или плагина, обновление на месте, отключение и удаление плагина); при выключенном экране (Doze) отслеживание теряет соединение и восстанавливается после пробуждения устройства, а на странице настроек можно запросить исключение из оптимизации батареи для непрерывного отслеживания.
- Базовая производительность: списки, поиск, загрузка, отправка и часовое ожидание в IDLE на локальном ящике из 10000 писем с вложением 50 MiB на JVM, Redmi и Sony записаны в `docs/dev/p6-performance-baseline.md`; документы писем ограничены (адреса, заголовки, дерево MIME и встроенные тексты имеют пределы), поэтому враждебный ввод не может разрушить сеанс.

### Частые вопросы

******

- **Как разобраться с `AUTH_FAILED`?** Убедитесь, что используется код авторизации или пароль приложения, а не пароль для входа, и что протокол включен в веб-настройках (IMAP и POP3 включаются отдельно); вызовите `client.test()`, чтобы отдельно увидеть результат и код ошибки для конечной точки приема и для SMTP. Для учетных записей с токеном `AUTH_FAILED` обычно означает истекший токен; при наличии `tokenProvider` плагин обновляет его и повторяет попытку один раз. Поля ошибки `code`, `details` и `retryable` подсказывают, имеет ли смысл повтор.
- **163 / 126 отвечают `Unsafe Login`?** IMAP-серверы NetEase отвергают соединения, не отправившие команду `ID`; плагин отправляет `ID` сразу после входа на каждом IMAP-соединении, поэтому такого быть не должно. Если это все же происходит, заново включите службу IMAP в веб-настройках и сгенерируйте новый код авторизации.
- **Поиск по-китайски ничего не находит?** Серверы по-разному обрабатывают поиск не по ASCII: Sina отвергает его (плагин сам переходит на клиентскую фильтрацию), а QQ и 163 отвечают нулем совпадений без ошибки (стандартный `fallback: 'client'` не срабатывает). Используйте на таких учетных записях `fallback: 'always'` и сужайте окно через `since` или `limit`; клиентская фильтрация по тексту загружает каждого кандидата и может быть медленной на большом ящике.
- **`mail.connect` прошел успешно, а первый `fetch` падает?** `connect` только открывает сеанс плагина и не обращается к почтовому серверу; вход выполняет первый сетевой метод (SMTP - при первой отправке). Чтобы проверить учетную запись заранее, вызовите `client.test()`.
- **Отслеживание останавливается после выключения экрана?** Doze в Android замораживает сеть фоновых приложений, поэтому отслеживание теряет соединение, а новые письма сообщаются через несколько минут после пробуждения устройства (плагин переподключается, как только Doze заканчивается). Для непрерывного отслеживания запросите исключение из оптимизации батареи кнопкой-подсказкой на странице настроек; отслеживание живет только пока выполняется скрипт и закрывается при его завершении.
- **Как подключить Outlook.com / Hotmail?** Microsoft отключила базовую аутентификацию для личных учетных записей, поэтому пресет не принимает пароль. Сохраните учетную запись на странице настроек плагина и выберите аутентификацию "Войти через Microsoft (браузер)": страница входа Microsoft откроется в браузере, в плагин вернется только код авторизации, а токен доступа плагин обновляет сам; затем скрипты подключаются по псевдониму. Скрипт по-прежнему может передать полученный в другом месте токен доступа как `accessToken` и обновлять его через `tokenProvider`. Если на странице учетных записей написано "требуется повторный вход", обновление было отклонено (вход отозван или истек): откройте меню учетной записи и выберите "Войти заново".
- **Что умеет учетная запись POP3?** Существует только `INBOX`, а `uid` - это строка UIDL; работают списки, чтение, загрузка, удаление и отслеживание опросом, тогда как флаги, перемещение, копирование, добавление, очистка и управление папками отвечают `UNSUPPORTED_OPERATION`; поиск выполняется на клиенте только по условиям конверта.

### Разрешения и безопасность

******

Плагин соблюдает явные границы:

- Точки входа Binder защищены разрешением подписи `org.autojs.permission.PLUGIN`, поэтому доступ к ним имеет только AutoJs6; других экспортируемых компонентов у плагина нет.
- Разрешение INTERNET служит для соединений IMAP, POP3 и SMTP с серверами, которые называет скрипт, а для учетных записей, вошедших через браузер, только для HTTPS-запросов к конечным точкам токенов Google (`oauth2.googleapis.com`) и Microsoft (`login.microsoftonline.com`): обмен кода авторизации, обновление истекающего токена доступа и отзыв токена Google по запросу. Других запросов плагин не делает и данных не собирает.
- Пароли и токены передаются от скрипта плагину в отдельных полях Binder, никогда не попадают в журналы, JSON-документы, сообщения об ошибках и отчеты о сбоях и хранятся в памяти только на время сеанса. Учетные записи, сохраненные на странице настроек, шифруются ключом Android Keystore и исключены из резервных копий. Токены входа через браузер хранятся так же: токен обновления никогда не покидает устройство, почтовому сеансу передается только токен доступа, и ни AutoJs6, ни скрипт не могут их прочитать; "Отозвать вход" сразу удаляет их.
- Соединения по умолчанию используют TLS (SSL или STARTTLS по требованию провайдера); незашифрованные соединения и самоподписанные сертификаты нужно явно запрашивать для каждой учетной записи.
- Разрешение REQUEST_IGNORE_BATTERY_OPTIMIZATIONS нужно только кнопке-подсказке на странице настроек: она показывает, может ли система приостанавливать плагин в фоне, и по запросу открывает системный диалог; плагин никогда не запрашивает исключение сам, и ни одна функция от него не зависит. Матрица отслеживания P5 измерила, зачем нужно исключение: когда экран выключен некоторое время (Doze), Android замораживает сеть фоновых приложений, отслеживание теряет соединение, его повторные подключения истекают по времени, а о новых письмах сообщается через несколько минут после пробуждения устройства (около четырех минут на Android 9; по окончании Doze плагин переподключается сразу); с исключением отслеживание остается подключенным.
- Четыре разрешения служат только фоновому наблюдению версии 1.1.0. FOREGROUND_SERVICE и FOREGROUND_SERVICE_SPECIAL_USE запускают службу наблюдения (тип `specialUse`, подтип `mail_background_watch`, потому что почтовое наблюдение - это открытое соединение в ожидании push от сервера, а не ограниченная синхронизация данных) с одним уведомлением низкого приоритета; POST_NOTIFICATIONS запрашивается на странице наблюдений только при включении наблюдения, чтобы уведомление показывалось на Android 13 и новее; RECEIVE_BOOT_COMPLETED стоит за переключателем автозапуска на той же странице, который по умолчанию выключен и включает приёмник только при включении. Служба запускается только со страницы наблюдений или по подписке хоста, подключается только к сохранённым учётным записям, держит секреты внутри процесса плагина, а пробуждающая рассылка в AutoJs6 несёт конверт письма (никогда не тело) и достигает только приёмника за сигнатурным разрешением PLUGIN.

Получайте плагин только со страницы официальных [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Angus-Mail/releases) или из центра плагинов AutoJs6. Пакеты из неизвестных источников могут не пройти проверку хоста или нести риски, даже если номер версии выглядит одинаково.

application id: io.github.supermonster003.autojs6.plugin.angus.mail
plugin id: angus-mail
engine: mail
variant: default
service action: org.autojs.plugin.MAIL
service category: mail
info action: org.autojs.plugin.INFO
aidl interface: org.autojs.plugin.mail.api.IMailPlugin
minimum host build: 5282 (6.8.0)

`AngusMailPluginService` реализует контракт хоста mail-api `org.autojs.plugin.mail.api.IMailPlugin` и отвечает на `org.autojs.plugin.MAIL` (категория `mail`). `AngusMailPluginInfoService` отвечает на `org.autojs.plugin.INFO` объектом PluginInfo. `WakeActivity` позволяет хосту активировать плагин.

- `Функция` Действия страницы учетных записей "Войти заново" (новый вход через браузер сохраняется в ту же запись) и "Отозвать вход" (токены записи сразу заменяются отозванным маркером, Google просят отозвать токен обновления, и учетная запись не работает до нового входа); `authHint` пресетов `gmail`, `outlook` и `office365` называет вход через браузер первым (`providers.json` версии 4); 35 новых строк на 11 языках; JVM-тесты для PKCE, запроса авторизации и разбора перенаправления, клиента токенов на сценарном транспорте, документа токенов, таблицы провайдеров, клиентов и URI перенаправления сборки, `AccountSecrets` (обновление, пометка отказа, отозванные записи, стирание) и объекта `oauth` в параметрах учетной записи, форме и документе учетных записей

Функция добавляет четыре разрешения, каждое объяснено в разделе безопасности README: FOREGROUND_SERVICE и FOREGROUND_SERVICE_SPECIAL_USE (служба наблюдения), POST_NOTIFICATIONS (её постоянное уведомление, запрашивается только при включении наблюдения) и RECEIVE_BOOT_COMPLETED (переключатель автозапуска на странице наблюдений, по умолчанию выключен).

Служба переднего плана `MailWatchService` типа `specialUse` ведёт включённые наблюдения на наблюдателях P5 (IDLE там, где сервер отправляет push, иначе опрос, переподключение с задержкой, немедленное переподключение при смене сети), пока не запущен ни один скрипт, и показывает одно уведомление низкого приоритета; каждое новое письмо добавляется в список записей наблюдения (последние 100 сводок конвертов, `MAX_TRIGGER_RECORDS`, без тела), а страница показывает состояние соединения, последнюю ошибку, записи и действие переподключения; переключатель автозапуска (по умолчанию выключен) включает приёмник `BOOT_COMPLETED`, который перезапускает службу после перезагрузки
- `Функция` Почтовый контракт версии 2 (`IMailPlugin.openTrigger` / `listTriggers`, `IMailTrigger`, `IMailTriggerCallback`, признак возможности `backgroundWatch`): хост подписывается на настроенное наблюдение с поколением и необязательным фильтром, сразу получает текущее состояние, затем `onStatus` (stopped, connecting, connected или failed с причиной и последней ошибкой) и `onMail(generation, seq, event)` для каждого подходящего письма; событие `mail` несёт идентификатор наблюдения, псевдоним, адрес, папку, конверт письма и `receivedAt`. У наблюдения не более 4 подписчиков (`MAX_TRIGGER_SUBSCRIBERS`); выключенное или неизвестное наблюдение и негодные параметры отклоняются состоянием `stopped` с причиной `refused`, `update` заменяет фильтр подписчика, `stop` завершает только подписку; без живого подписчика каждое событие уходит в AutoJs6 явной рассылкой `org.autojs.autojs6.action.MAIL_TRIGGER` за его сигнатурным разрешением `PLUGIN`, которая запускает задачу хоста "При получении письма", даже когда ни один скрипт не выполняется (`MailTriggerBinderTest` на AVD API 37; `TriggerStoreTest`, `TriggerFilterTest`, `TriggerConfigTest`, `TriggerDocumentsTest`)
- `Функция` Почтовое ядро получило документы и правила триггеров, общие для страницы, службы и Binder (`TriggerConfig`, `TriggerFilter` с подстроками отправителя и темы без учёта регистра, `TriggerOptions`, `TriggerStatusDocument`, `TriggerEventDocument`, `TriggerRecord`), потолки `MAX_TRIGGERS`, `MAX_TRIGGER_SUBSCRIBERS`, `MAX_TRIGGER_RECORDS` и `MIN_TRIGGER_INTERVAL_MS` (3 с, ограничение хоста на задачу), а наблюдатели сообщают `onConnected`, чтобы фоновое наблюдение показывало `connected`, как только папка открыта

```powershell
.\gradlew.bat :app:assembleDebug
```

.\gradlew.bat :mail-core:test :app:testDebugUnitTest :app:assembleDebugAndroidTest

.\gradlew.bat :app:assembleRelease
```

.\gradlew.bat :app:appendDigestToReleasedFiles

py .python\generate_markdown.py --check

Запустите `py .python/generate_markdown.py --check`, чтобы проверить все сгенерированные артефакты.
